Shows the CPU, memory, disk, network and NVIDIA GPU usage of the machine the Paseo daemon runs on, and its CPU and GPU temperatures, as one line in the sidebar footer.

The line reads like the built-in usage summary, one item per figure: CPU usage, CPU temperature, RAM, disk, network, and on a host with an NVIDIA GPU its usage, temperature, video memory and power draw in watts. Percentages (CPU, RAM, disk, GPU, video memory) get a small meter when the sidebar is wide enough; download and upload speed sit side by side under one icon. The disk figure adds all local disks together; with several GPUs the line shows their average load, the hottest card, and their video memory and power added together. Meters and percentages turn yellow above 70 percent and red above 90 percent, temperatures at 80 and 90 °C; on macOS the RAM color follows the system's memory pressure instead (see below). On a narrow sidebar the items are dropped in this order until the line fits: network, disk, video memory, GPU power, GPU temperature, CPU temperature. CPU, RAM and GPU usage always stay. Press the line for a popover with about three minutes of history for each metric (CPU usage and temperature, RAM, download, upload, and GPU usage, temperature, video memory and power, the power drawn against its limit), the usage of each local disk, and uptime and load average.

With the plugin on several connected hosts, the line shows the host the app has selected, which follows the host of the chat you have open. The sliders button in the popover, or the plugin's settings for a host under Settings, turns each of the nine figures on or off for that host. The choice is kept on this device only, so a phone and a laptop can show different metrics; with every metric off, the line disappears while that host is selected.

The daemon samples the host every two seconds, disks every thirty, and keeps the history in memory. History resets when the plugin reloads or the daemon restarts.

Percentages below 10 show one decimal, so a nearly idle host reads 0.4% rather than 0%. On Linux, CPU usage comes from `/proc/stat`; I/O wait counts as idle and steal time, which a VPS loses to its hypervisor, counts as busy. Memory uses the available-memory figure from `/proc/meminfo` on Linux, so the page cache is not counted as used. On macOS, RAM follows Activity Monitor's Memory Used: app memory, wired memory and the compressor, read from `vm_stat`. Cached files are left out because macOS frees them as soon as an app needs the room; the popover shows them on a separate line. A Mac often runs at high usage with no shortage, so there the RAM color follows the kernel's memory pressure level (`kern.memorystatus_vm_pressure_level`): yellow at warning, red at critical, never because of the percentage alone. Sizes use binary units (KiB, MiB, GiB), so a 994.6 GB disk reads 926.3 GiB. Network speed sums all interfaces except loopback and common virtual ones (veth, docker, bridge). Disks are the filesystems in `/proc/mounts` backed by a block device (plus ZFS), each device counted once; network mounts, memory-backed filesystems and read-only images such as snap packages are left out. Disk percentages follow `df`: space reserved for root counts as neither used nor free. On macOS the disk is the APFS container of the root volume, so its usage covers every volume in the container (system, data, VM and others), and the popover labels it that way; apps that show the data volume alone report a little less. Network speed and the disk list need Linux; on other systems only CPU, RAM and the root disk are shown. CPU temperature needs Linux: it is the CPU's own sensor in `/sys/class/hwmon` (the package sensor of Intel's `coretemp`, `Tdie` or else `Tctl` of AMD's `k10temp`, or `cpu_thermal` on ARM boards), or else the `x86_pkg_temp` thermal zone; most virtual machines expose none. Windows and macOS show no CPU temperature: Windows offers only ACPI thermal zones to a normal user, which on a desktop board measure the board rather than the CPU, and the CPU sensor itself needs administrator rights or a driver such as LibreHardwareMonitor's; macOS needs root for it. GPU figures come from `nvidia-smi`, which the NVIDIA driver installs on Linux and Windows; a host without it shows no GPU. With several NVIDIA GPUs the line and its history show their average load, the hottest card, and their video memory and power added together, and the popover lists each card.

The plugin only reads local system counters. On macOS it runs `/usr/bin/vm_stat` and `/usr/sbin/sysctl -n kern.memorystatus_vm_pressure_level` every two seconds for the memory figures; on Linux and Windows it runs `nvidia-smi` every two seconds, without a shell and with a time limit; it runs nothing else. On Linux it also reads the CPU temperature file in `/sys` every two seconds. The host name and these statistics are shown to every Paseo client connected to the daemon, including remote ones; the plugin contacts no other service.
